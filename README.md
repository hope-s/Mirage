# Mirage 🌫️

تانل چندپروتکلی و خودترمیم برای اتصال سرور ایران به سرور خارج. کل برنامه یک فایل اجرایی است، به هیچ پکیجی نیاز ندارد و پنل مدیریت وب داخل خودش است.

```
کاربر ──▶ [ایران: Mirage] ══ TLS ═══════╗
                            ══ TCP ═══════╬══▶ [خارج: Mirage] ──▶ X-UI / اینترنت
                            ══ WebSocket ═╣
                            ══ CDN (پشتیبان)╝
```

## امکانات

| بخش | توضیح |
|---|---|
| **پروتکل‌ها** | TCP خام، TLS (از بیرون شبیه HTTPS)، WebSocket، WebSocket روی TLS، عبور از CDN مثل Cloudflare، **KCP روی UDP** و **KCP روی fake-TCP** |
| **پکت‌لاست بالا** | KCP با تصحیح خطای FEC: بسته‌های گم‌شده بدون ارسال دوباره بازسازی می‌شوند. در تست با ۳۰٪ پکت‌لاست هم بدون خطا کار می‌کند |
| **حالت‌های سرعت KCP** | `normal` · `fast` · `fast2` · `fast3` · `turbo` (هرچه سریع‌تر، پینگ کمتر روی لینک خراب و مصرف پهنای باند بیشتر) |
| **جهت اتصال** | مستقیم (ایران به خارج) یا معکوس (خارج به ایران)، مثل Backhaul |
| **ورودی‌ها** | port forward برای TCP و UDP (مثل Backhaul) و SOCKS5 با پشتیبانی UDP برای outbound در X-UI (مثل Hedioum) |
| **سوییچ خودکار** | ترافیک بین همه‌ی لینک‌های سالم پخش می‌شود و هر اتصال جدید روی لینکی می‌رود که کمترین پینگ و بار را دارد. اگر لینکی قطع شود، بدون دخالت شما از لینک‌های دیگر و در آخر از لینک‌های پشتیبان استفاده می‌شود |
| **تانل پشتیبان** | لینک‌هایی که «پشتیبان» علامت خورده‌اند (مثلاً CDN) فقط وقتی استفاده می‌شوند که هیچ لینک اصلی سالمی نمانده باشد |
| **تشخیص اتصال کند** | پینگ هر اتصال مدام سنجیده می‌شود. اگر یک اتصال خیلی کندتر از حالت عادی لینک شود (مثلاً به‌خاطر محدودسازی تک‌اتصال)، بدون قطع شدن کاربران با یک اتصال تازه جایگزین می‌شود |
| **ریستارت خودکار** | اتصال‌های مرده (حتی آن‌هایی که بی‌صدا بسته‌ها را دور می‌ریزند) ظرف چند ثانیه تشخیص داده و دوباره وصل می‌شوند. اگر ۳ دقیقه هیچ تانلی برقرار نباشد، کل هسته از نو ساخته می‌شود و systemd هم در صورت crash برنامه را بالا می‌آورد |
| **تنظیم خودکار سرعت** | اندازه‌ی بافر (window) هر استریم مثل QUIC خودکار بزرگ می‌شود تا روی لینک پرسرعت از تمام ظرفیت استفاده شود و روی لینک کند حافظه هدر نرود. تعداد اتصال‌های موازی هم بر اساس بار بیشتر و کمتر می‌شود |
| **پروفایل** | ⚡ سرعت (کمترین پینگ و CPU) · ⚖ متعادل · 🛡 استتار (padding کامل). از پنل با یک کلیک عوض می‌شود |
| **امنیت** | تبادل کلید X25519 با forward secrecy، رمزنگاری AES-256-GCM، کلید مشترک که هیچ‌وقت روی شبکه فرستاده نمی‌شود، جلوگیری از replay، طول بسته‌های مخفی و padding تصادفی |
| **ضد probe** | هر کسی که بدون کلید وصل شود یک سایت معمولی با هدر nginx می‌بیند (یا سایت واقعی شما اگر `fallback` تنظیم شده باشد)، یا هیچ پاسخی نمی‌گیرد |
| **محافظت سرور خارج** | از داخل تانل نمی‌شود به localhost یا شبکه‌ی خصوصی سرور خارج (مثلاً پنل X-UI) رسید، مگر پورت‌هایی که خودتان اجازه داده‌اید |
| **چرخش اتصال‌ها** | هر اتصال بعد از ۲۰ تا ۶۰ دقیقه (زمان تصادفی) بی‌صدا با اتصال تازه عوض می‌شود |
| **پنل وب** | آمار و نمودار زنده، وضعیت لینک‌ها و اتصال‌ها، روشن و خاموش کردن لینک‌ها، ویرایش فورواردها، تغییر پروفایل، سرعت‌سنجی، لاگ‌ها و ویرایش کانفیگ |
| **مصرف منابع** | در حالت بیکار حدود ۱۰ تا ۱۵ مگابایت رم. زیر بار سنگین بیشتر می‌شود و بعد از تمام شدن بار، حافظه به سیستم برمی‌گردد. رمزنگاری از شتاب‌دهنده‌ی سخت‌افزاری AES-NI استفاده می‌کند |
| **بهینه‌سازی شبکه** | نصب‌کننده BBR و fq را فعال می‌کند و بافرهای TCP را بزرگ‌تر می‌کند |

## نصب (۲ دقیقه)

روی **هر دو سرور** با کاربر root این دستور را بزنید. به هیچ پیش‌نیازی (Go، Python و…) نیاز نیست:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/hope-s/Mirage/main/install.sh)
```

اگر سرور ایران به GitHub دسترسی نداشت، فایل `mirage-release.tar.gz` را از [Releases](https://github.com/hope-s/Mirage/releases) دانلود کنید، روی سرور آپلود کنید و این را بزنید:

```bash
tar xzf mirage-release.tar.gz && cd mirage && sudo bash install.sh
```

بعد از نصب، منوی برنامه باز می‌شود:

1. **سرور خارج:** گزینه‌ی `1` را بزنید و به سؤال‌ها جواب دهید. در آخر یک **توکن** نمایش داده می‌شود.
2. **سرور ایران:** گزینه‌ی `2` را بزنید و توکن را paste کنید. بعد مشخص کنید ترافیک کدام پورت‌ها به کدام اینباند X-UI در سرور خارج برود (مثلاً `443=2096`).

همین. بعد از این هر وقت `mirage` را اجرا کنید منو باز می‌شود.

### دستورهای مستقیم (بدون منو)

```bash
# سرور خارج: TLS روی 443، TCP روی 8880، WebSocket روی 8080 به‌عنوان پشتیبان، با اجازه‌ی دسترسی به اینباند X-UI روی 2096
mirage setup kharej -tls 443 -tcp 8880 -ws 8080 -backup ws -allow-local 2096
mirage install

# سرور ایران: پورت 443 ایران ← اینباند 2096 خارج، و یک SOCKS5 برای outbound در X-UI
mirage setup iran -token 'MRG1....' -forward 443=2096 -socks 40001
mirage install
```

| دستور | کار |
|---|---|
| `mirage` | منوی تعاملی |
| `mirage status` | لینک‌ها، اتصال‌ها، پینگ و ترافیک |
| `mirage speedtest` | سرعت‌سنجی واقعی تانل (روی سرور ایران) |
| `mirage panel` | آدرس، نام کاربری و رمز پنل |
| `mirage token` | نمایش دوباره‌ی توکن (روی سرور خارج) |
| `mirage restart` / `logs` / `uninstall` | ری‌استارت، لاگ زنده، حذف کامل |
| `mirage install` | نصب یا آپدیت (با باینری جدید اجرا کنید) |

## سناریوها

**اختلال شدید و پکت‌لاست بالا:** یک لینک KCP اضافه کنید، مثلاً `-kcp 4500 -kcp-mode fast3 -fec 10:5`. پورت UDP را در فایروال سرور خارج باز کنید. هرچه عدد دوم FEC بیشتر باشد، پکت‌لاست بیشتری تحمل می‌شود و پهنای باند بیشتری هم مصرف می‌شود.

**وقتی UDP بسته است ولی TCP زیر اختلال کند می‌شود:** از `-ftcp 8443` استفاده کنید. ابتدا یک handshake واقعی TCP انجام می‌شود و بعد بسته‌ها مستقیم ساخته می‌شوند، پس از بیرون شبیه TCP است ولی کند شدن TCP زیر پکت‌لاست را ندارد. روی هر دو سرور به لینوکس و root نیاز دارد.

**مثل Backhaul (port forward):** روی سرور ایران `-forward 443=2096` بگذارید. کاربرها کانفیگ اینباند سرور خارج را می‌گیرند و فقط آدرسش را به IP ایران و پورت ۴۴۳ تغییر می‌دهند. قوانین routing در X-UI خارج (مثلاً فرستادن یک سایت از WARP) روی همین ترافیک هم اعمال می‌شود.

**مثل Hedioum (SOCKS):** روی سرور ایران `-socks 40001` بگذارید و در X-UI ایران یک outbound از نوع socks به `127.0.0.1:40001` بسازید.

**وقتی خارج به ایران وصل نمی‌شود** (حالت عادی): حالت مستقیم.
**وقتی ایران به خارج وصل نمی‌شود:** روی سرور خارج از `-reverse IP_ایران` استفاده کنید و پورت‌ها را در فایروال سرور ایران باز کنید.

**CDN به‌عنوان پشتیبان:** یک ساب‌دامین بسازید (مثلاً `t.example.com`) و در Cloudflare ابر نارنجی آن را روشن کنید (SSL روی حالت Flexible). در سرور خارج با `-cdn t.example.com -cdn-origin-port 80` راه‌اندازی کنید. اگر همه‌ی IPهای مستقیم فیلتر شوند، ترافیک خودکار از CDN رد می‌شود. برای SSL حالت Full از `-cdn-origin-tls -cdn-origin-port 443` استفاده کنید.

**چند پورت برای یک پروتکل:** مثلاً `-tcp 8880,2095,9443` روی چند پورت گوش می‌دهد و هر اتصال جدید یکی را تصادفی انتخاب می‌کند. اگر یکی بسته شود، بقیه کار می‌کنند.

## پنل

آدرس و رمز را با `mirage panel` ببینید. پنل روی HTTPS با گواهی self-signed اجرا می‌شود و فقط از یک مسیر مخفی و تصادفی در دسترس است. برای هر آدرس دیگری یک صفحه‌ی ۴۰۴ معمولی nginx نشان داده می‌شود. بعد از ۵ تلاش ناموفق برای ورود، آن IP ده دقیقه مسدود می‌شود.

## کانفیگ دستی

کانفیگ در `/etc/mirage/config.json` است. بعد از ویرایش با `mirage check` درستی‌اش را بررسی کنید و با `systemctl reload mirage` اعمال کنید. اگر کانفیگ جدید اجرا نشود، کانفیگ قبلی خودکار برمی‌گردد.

| کلید | توضیح |
|---|---|
| `profile` | `speed` / `balanced` / `stealth` |
| `dial[].conns` / `max_conns` | حداقل و حداکثر اتصال موازی (مقیاس خودکار) |
| `dial[].backup` / `disabled` | پشتیبان بودن / خاموش بودن لینک |
| `listen[].fallback` | `host:port` یک سایت واقعی که probeها به آن فرستاده شوند |
| `allow_local` | سرویس‌های محلی سرور خارج که از تانل قابل دسترسی‌اند |
| `rotate_min` / `rotate_max` | بازه‌ی چرخش اتصال‌ها به ثانیه (`0` یعنی خاموش) |

## محدودیت‌ها

- **فقط روی شبکه‌ی واقعی معلوم می‌شود.** همه‌ی بخش‌ها روی localhost تست خودکار دارند، ولی رفتار فیلترینگ هر اپراتور فرق می‌کند. برای همین چند پروتکل گذاشته شده تا اگر یکی بسته شد، بقیه کار کنند.
- **اثر انگشت TLS:** ClientHello مربوط به کتابخانه‌ی استاندارد Go است و دقیقاً شبیه Chrome نیست. اگر TLS زیاد قطع شد، از TCP، WebSocket یا CDN استفاده کنید.
- **fake-TCP** فقط روی لینوکس و با root کار می‌کند و یک قانون iptables اضافه می‌کند که موقع بسته شدن برنامه پاک می‌شود.
- **ساعت دو سرور** نباید بیش از ۲ دقیقه با هم اختلاف داشته باشد (نصب‌کننده NTP را روشن می‌کند).
- **ممیزی امنیتی مستقل نشده.** الگوریتم‌ها استاندارد هستند، ولی کد پروتکل جدید است.
